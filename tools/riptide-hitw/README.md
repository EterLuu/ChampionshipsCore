## 十二格木墙（目录 v4）

参考运行地图 bench1–32 的实际 Sponge 快照：立柱使用 `stripped_spruce_wood[axis=y]`，横梁使用 `axis=x`；上下半砖、上下楼梯及其东西朝向均保留。细杆改用指定东西连接的云杉栅栏，薄竖片改用打开的云杉活版门。注意活版门 `facing=east,open=true` 位于方块西边，反之亦然；栅栏碰撞高 1.5 格；相邻但不互连的栅栏保留中间 0.75 格窄缝（如 bench13/20），不自动补横杆。正式比赛和试玩都禁止玩家点击改变活版门状态。

- 从原图 14 列仅删除 2 列，优先重复实心轮廓，再考虑重复轮廓；没有重复时选择差异最小、细节最少的列。原先只有部分列有建筑的墙，其实体跨度可能小于 12 格。每张图的删除列都记录在 `adapted.json`，不再把整段洞口合并成一列。
- 保留各洞口、楼梯和细杆的相对顺序。现有甲板仍为 7×9，外侧形状可超出甲板；先按普通移动保留或局部适配门洞，最多一格门槛，X 组可使用地面 1.5 格潜行洞。目录 v3 进一步处理一格完整门槛上方的 1.5 格洞口：其他有效洞口剩余面积至少 3 格² 时，将顶半砖换为完整木块；否则删除顶半砖，留下可跳跃的两格洞。没有将每一个高窗都改为可通行洞，也没有增加跳跃提升。
- `sources.json` 固定原图 URL、半格轮廓，以及从原 PNG 细部补充的方块分类。运行时完全离线；工具重建也只依赖 Python 标准库。
- `adapted.json` 记录最终方块、删列、局部修改及普通移动通行位置；`preview.html` 展示原图和按方块碰撞尺寸绘制的木墙侧视图。原图加载需要联网。薄片与细杆是按 bench 材料体系转译，未移植黏液物理和活塞运动。

运行 `python3 tools/riptide-hitw/build_catalog.py` 重建内置 JSON、默认地图条目和对照页。每条仍为可独立编辑、复制、停用、删除的 Sponge v3 建筑；15×5×15 快照是保存空间，墙体占单个纵向平面。

## 连续墙组与侧墙

地图 v24，生成器 v23。`course.wall-groups: true`、`course.side-sweeps: true` 可分别关闭普通墙组和侧墙替换；末段三连规则独立生效。当前赛道配额为15穿越/5解题/5停顿（3踩色、2侧向）/5节奏；连续墙组不增加逻辑关卡数。

- 前20%保留单墙；20%后可压紧相邻双墙，40%后可用三墙，80%后固定三连。穿越墙体整场最多一次，正向、侧向及末段新增墙共用额度，相同快照的副本不能增加额度，不再保存抽取次数属性。连续正向墙和相邻侧墙的横向通行位置必须错开，仅改变跳跃或潜行动作不算换位；侧墙检查同时考虑来向和镜像。
- 间距按该段最大船速和所有已知出口到下一个可用入口的最短换位耗时计算，预留清出前墙、起跳与潜行切换时间；横向速度扣除自行跟上木筏所需的前向分量。三墙使用“前松后紧”或“双连后缓”节奏。跨加速点也按高速一侧计算。数学和踩色位置不变，组间继续采用原来的保守衔接检查。
- 第二次加速（40%）后最多两个独立穿越墙位改为侧墙段；40%–60% 每组两面，第三次加速（60%）起每组三面。每面从同一启用的穿越池按权重和难度抽取未使用墙体；来向独立随机，允许左左、右右等连续同侧组合。编排固定建筑、洞口和来向，试玩不会重新抽取。已知目录洞口须落在甲板可站立范围内；没有洞口元数据的自建建筑仅单独出现，不添加路径搜索。
- 木筏到位后停稳，每面预告30 ticks，以该航段船速逐格推进真实建筑。保留建筑方块、旋转后的朝向和方块实体数据，不采样玩家或墙体碰撞形状、不检测触墙淘汰，沿用穿越的离筏与掉落判定；不再固定第二面潜行。起点为甲板半宽外5格，再加建筑纵向半厚度，确保厚建筑也完整位于甲板外。每次移动及结算、退出试玩、断线、reset、卸载时恢复原方块；完成整组后恢复航行并保留移动预算。
- 试玩暂存并清除管理员原有药水效果，末段同步速度 I，结束时恢复原效果。正式比赛与试玩共用侧墙控制器；预览列表标记连墙和侧向连墙。选择墙组中的任意一面试玩会带上整组，单独编辑某个变体始终展示原始未镜像快照。单关试玩、赛道预览及正式比赛中的所有穿越建筑（含自建墙）均可随机左右镜像；每面侧向墙独立抽取镜像，与来向分别固定在编排和日志中。侧墙通过预览列表中的单关试玩即可验收。
- 只对与目录**快照完全一致**的条目使用内置通行数据，相同快照的副本也可识别。bench和用户改过的墙保留独立建筑；没有恢复管理员保存建筑时的路径搜索或通行高度校验。

总航程耗时包含各加速阶段的航行、踩色与侧墙停留；每面侧墙耗时为30 + ceil（2 ×（甲板半宽 + 5 + 建筑纵向半厚度）× 20 / 船速）ticks，逐面求和。编排估算、正式比赛与试玩共用时间线，超出比赛限时的编排会被拒绝。

## 升级与验收

`legacy-v1.json` / `legacy-v2.json` 保存旧目录快照用于识别。目录迁移 v1/v2→v3 仅为未改动的旧导入墙更新 building 与 difficulty，保留 ID、名称、启停、权重及其他属性；不恢复已删除的条目，不覆盖 bench 或用户改过的导入墙。首次导入仍按 ID 去重。运行配置和源码默认资源一致，关卡池上限仍为 512。

此次迁移不修改地图发布 revision 或已有世界；正式比赛在准备时重新生成赛道。需通过既有流程重启 cc-core 后生效。后续用户编辑保存建筑仍需重新发布。

测试覆盖全部 NBT 的方块、偏移和碰撞通行数据；200 个种子的配额、墙组、镜像、难度、衔接、侧墙数量和耗时；40%/60%阶段边界、独立来向、四个朝向的建筑旋转；侧墙推进不检测玩家接触；升级保留修改/删除；原方块恢复及试玩整组选择。自动验证不能代替移动木筏上的真人操作和客户端显示验收。

仅 Core 使用此玩法；Bingo Worker 没有对应实现，共享协议与展示未变化。

## 通行面积评级与现有地图更新

`apertures.py` 离线读取 Sponge v3 快照，在甲板横向七格、脚面以上三格范围内计算可用门洞截面积（格²）。识别半砖、直楼梯、栅栏和活版门的碰撞尺寸；洞宽至少 0.6 格，地面和可自动踏上的半格台阶允许 1.5 格潜行，一格门槛要求至少 1.8 格净空。高窗、窄缝不计入；重叠洞口面积去重，厚建筑取各非空墙面的最小值。评级为：面积 ≥6 → 难度1；3≤面积<6 → 难度2；面积<3 → 难度3。它是尺寸评级，不是连续路径可达性证明；其他方块保守视为完整方块。

当前地图的 234 个已保存穿越变体一起重评（含 bench1–35、acc 和 198 个导入墙）。bench7 的两处悬空半格门洞改为两格空气；9 个导入变体共10处顶半砖按剩余通路封实或删除。贴地潜行洞不变。评级依然保存在原 difficulty 字段，可在编辑器手动调整；后续修改建筑不会暗中覆盖管理员的评级，可按需重新运行此工具。

使用 `python3 tools/riptide-hitw/update_map.py <raft.yml> --report /tmp/riptide-aperture-report.json` 预览；加 `--apply` 应用。工具需要 PyYAML，目录重建仅使用标准库。只改 PASS 的 building/difficulty 和配置版本标记，保留其他配置文本及发布状态；运行中的地图如正在编辑，须先退出编辑再执行，应用后通过既有流程重启 cc-core，避免旧内存回写。

验证：`python3 -m unittest discover -s tools/riptide-hitw/tests`，以及根目录 `mvn -B -o -pl championships-core -am package`。

## 按加速节点筛选难度

正向穿越：0–20% 仅难度1，20–40% 仅难度2，40%以后仅难度2或3。侧向门：40%前不开启，40–60%仅难度1或2，60%以后仅难度2或3。边界与20/40/60/80%的加速节点相同；连续数学门移动邻关和连墙压缩后都重新复核正向难度。指定档位无足够关卡时编排失败或跳过侧墙，不回退到已禁止的档位。

镜像沿建筑自身横向翻转，再旋转到航线或侧墙来向；楼梯、半砖、活版门朝向和方块实体随完整方块状态一起变换。施工编辑保持原始建筑；数学红蓝门与踩色不使用穿越镜像。地图规则默认资源与运行配置同步，需重启cc-core；现有建筑、评级及发布状态不变，无需重新发布。
