# 激流勇进关卡与编排

这份指南帮助管理员调整关卡池并验收地图。玩法与命令入口见 [游戏指南](01-games.md#激流勇进)，开发职责见 [开发指南](../04-development/01-development.md)。地图配置格式为 v28（`RiptideRushConfig.getLatestVersion`），赛道规划器版本为 v30（`RiptideCoursePlanner.VERSION`）；两者分别标识配置结构与编排算法。关卡池为 `course.pool`，数量、权重和启停以所选地图配置为准。

## 调整地图

通过 `/cc map edit riptide` 选择地图，在穿越、解题、停顿和节奏页面设置配额。停顿配额通过 `course.stopped-allocation` 分给踩色、躲避和侧向挑战。内置模板为 12 穿越、5 解题、8 停顿、5 节奏；已有地图可以不同。关卡池条目保存独立 ID、名称、类型、变体、启停、权重和难度。

起点、方向、基准终点和 330 秒限时由自动布局设置。每轮先生成完整计划，再构造赛道；固定种子只在相同配置、建筑和生成器版本下重现。编排必须同时满足配额、建筑唯一性、难度、通行时间和总限时，池不足时先完善地图，不能以复用墙体绕过约束。

`course.layout.adaptive` 默认关闭，保持既有地图的 500 格边界。启用前必须先扩建并保存发布模板，预留最长赛道、木筏前后沿、两格清理缓冲、两侧障碍边距及清理高度；起点沿 +Z 方向航行，650 格终点对应 Z=539.5。配置了 `course.finish-platform` 的终点建筑跟随每轮实际终点移动；其完整占地与恢复背景均须纳入地图预留空间。其他固定布景放在生成范围之外。

| `course.layout` 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `minimum-length` | 500 | 可接受的最短赛道，格 |
| `maximum-length` | 650 | 地图已预留的最长赛道，格 |
| `transition-seconds` | 1.5 | 独立关卡间最短航行时间，不替代已有换位、解题及出发反应要求 |
| `clearance-blocks` | 6 | 独立关卡实际占用边缘之间的最小净距 |
| `time-reserve-seconds` | 10 | 从比赛限时中留出的余量，估计耗时必须小于剩余预算 |

开启后，编排在长度范围内从短到长尝试最多七个候选，包含最短和最长值；每个候选重新计算五段速度、难度、组合和末段。关卡按照实际建筑与停船甲板占用调整位置，空间不足时延长，不自动减少逻辑关卡配额。组合内部沿用自身节拍要求。全部候选失败时报告长度范围和时间预算；这表示本次有界搜索未找到方案，不能作为数学上的不可行性证明。

实际终点冻结在每轮计划中，建筑生成、整条/单关试玩、预热、计时和比赛进度共用这份长度。生成时清理整个预留区域，避免较短赛道留下旧终点或关卡。`course.finish-platform.building` 和 `background` 是成对的 Base64 Sponge v3 方块快照：建筑以终点甲板为原点，背景以起点甲板为原点，局部 +Z 为航行方向，+X 为横向。建筑须位于木筏前沿之后；背景覆盖最短至最长赛道的全部建筑落点，保存未放置平台时的原始水面、空气和布景。每次正式生成、预览与试玩先分批恢复背景，再生成赛道并放置完整终点建筑；告示牌、容器及方块方向保留。发布模板即使包含上次预览的平台，下一次生成仍恢复同一背景，不累积旧平台。两键都为空时保持无移动建筑的地图行为，只有一键或范围不足时拒绝生成。为已有地图接入时，先从原建筑提取快照并保存干净背景，再同批发布配置与插件；不能用当前已生成平台的世界替代干净背景。编辑预览显示实际长度、独立关卡数、展开挑战数、最短衔接航行时间，以及包含全部停船和出发等待的预计耗时。新增布局键可增量加入 v28 地图；升级不自动启用，已有池、数量和发布状态保持不变。

比赛结束后的地图恢复重新加载发布模板，不保留上一轮随机长度对应的平台位置。接入移动终点建筑时，还须将发布模板中的完整平台放到基准终点旁并清除原位置；仅更新生成配置不会改变结束后或未生成预览时的编辑布局。验收分别检查比赛进行时的平台与本轮终点衔接，以及结束恢复后的平台与基准终点衔接。若先更新发布模板而保留正在编辑的旧世界，再次发布前须同步修正编辑世界中的平台，避免旧位置被重新保存。

末段扩展关卡需要更多空间时，编排可将边界处的完整逻辑关卡前移到上一速度区间，并向前调整相邻间距；关卡数量、建筑唯一性、难度及末段内的三连规则继续校验，不以压缩停顿后的反应距离换取空间。

穿越建筑可现场施工、保存、复制、停用或删除。新空白建筑在保存前保持停用。相同建筑快照的副本共用整轮使用额度；修改后的自建建筑只使用自己保存的形状。建筑或规则改变后重新校验并发布。

## 木筏和淘汰

正式赛首轮的固定 90 秒规则体验场地见 [规则体验场地](08-riptide-introduction.md)。

木筏按航程的 20%、40%、60%、80% 节点切换速度。正常选手保留游戏的同队显隐策略；旁观身份、互见、完整 Tab 和游戏资格使用 [统一旁观契约](../04-development/03-spectator-visibility-contract.md)。出生时清零速度和下落距离并处理碰撞，清理时恢复原状态。

掉落按每 tick 的脚部支撑和边界采样判断：脚底低于甲板超过 0.5 格，或无支撑且越过水平余量、进入液体时开始计时；连续出界 20 tick 才确认，回到安全位置会清零。护盾救回和场地清理重置计时。死亡与断线仍可淘汰当前轮选手，出局后转为旁观。

正式赛进行三轮独立计分。每轮开赛重新确认在线参赛者；当前轮未出场者或断线者重连后只旁观。一次检测周期内的淘汰作为一批结算，同批互不获得生存分，仍存活者按该批每人获得 4 分。存活者或最后一批出局者并列第一，前三名奖励 100/70/30 分，并列按人数跳位。

## 各类关卡

| 类别 | 玩家需要做什么 | 地图调整入口 |
| --- | --- | --- |
| 穿越 | 随木筏通过建筑洞口，连续墙需要换位 | 建筑池、难度、权重与启停 |
| 解题 | 根据算术或观察题选择左右答案 | 数字范围、题型和数量 |
| 踩色 | 在每个小轮结束时踩中目标材料，可跳跃 | 材料变体和停顿分配 |
| 躲避 | 在停船期间避开逐只刷新的冲刺生物 | 生物变体和停顿分配 |
| 侧向 | 停船后依次通过横向移动的墙 | 与穿越共用建筑池 |
| 节奏 | 跟随红绿灯和音符通过动态闸门，木筏不停 | 节奏变体、权重和数量 |

关卡先由去皮云杉木立面遮挡，在木筏接近时恢复。连续墙和侧向墙逐面显现；结束或取消恢复占用的原方块，不改已保存快照。

正向穿越前 20% 使用难度 1，20%–40% 使用难度 2，后续使用难度 2/3。侧向挑战从 40% 后出现，40%–60% 使用难度 1/2，后续使用难度 2/3。连续墙根据洞口元数据、来向和镜像检查换位及动作时间；未知洞口的自建建筑仅单独出现。目录来源和通行口径见 [HITW 目录指南](07-riptide-hitw-catalog.md)。

躲避关停船 9 秒，前 1 秒准备，每关固定来向并逐只随机刷新。生物速度、间隔和在场上限按航程分五档；满员时跳过刷新，离开甲板或落到地板下会回收。亡灵关闭日间燃烧，水平碰撞宽度为 0.6 格。正式赛与试玩共用 [冲刺调度器](../../championships-core/src/main/java/ink/ziip/championshipscore/api/game/riptiderush/mechanics/RiptideDodgeSchedule.java)。

解题上行显示算式或线索，下行显示问题和左右选项。观察题包含数颜色、找第几项、找最大最小、数奇偶和找唯一项；末段解题可转为三面侧向答题，左侧及中央铺红色，右侧铺淡蓝色，每面分别结算。

数学题只在玩家通过前一关后预览；中间有停顿关时，还须等木筏完成停顿并恢复前进。停顿关后的移动关继续按速度和换位需求留出反应距离，正向解题至少预留 4 秒航行距离，不能将停船时长计入；题目显示仍受 `math.preview-blocks` 和 4 秒上限约束。正式赛和编辑器试玩共用这些规则。

节奏门使用铁块、红绿顶灯和音符提示；窗口根据节拍开合，关闭时处理与墙体重叠的身体，船尾通过或取消后恢复原方块。节奏关不计停船耗时，也不提供施工编辑。踩色整关、侧向整组和末段侧向解题完成后等待 40 tick 再恢复航行，等待仍扣比赛时间并检查掉落。

## 四拍节奏门

以下变体以四拍循环，全高开口可正常站立通过。每拍至少 16 tick（0.8 秒），低速时随周期延长；“左/右”以未镜像的关卡坐标为准，镜像时互换。玩家选择合适的开口通过一面门，无需在同一面门内完成全部换位。

| 变体 | 名称 | 一周期开口顺序 |
| --- | --- | --- |
| `TWIN_ORBIT` | 双星公转 | 双侧单格 → 内侧双单格 → 中央单格 → 内侧双单格 |
| `CENTER_RELEASE` | 中心放流 | 中央三格 → 中右五格 → 全开 → 中左五格 |
| `EDGE_RELAY` | 岸线接力 | 左岸两格 → 左中两格 → 右中两格 → 右岸两格 |
| `THREE_LANES` | 三径轮转 | 左岸两格 → 中央单格 → 右岸两格 → 中央三格 |
| `SPLIT_HOLD` | 双岸延音 | 双岸保持两拍 → 中央三格 → 全开 |
| `TRAVEL_PAUSE` | 行进休止 | 左三格 → 中央三格 → 关闭 → 右三格 |
| `NARROW_WIDE` | 窄宽应答 | 左内单格 → 左三格 → 右内单格 → 右三格 |
| `CHECKER_PULSE` | 间列脉冲 | 偶数列 → 奇数列 → 中央三格 → 全开 |
| `SIDE_LOCK` | 侧门切分 | 左三格 → 关闭 → 右三格 → 中央三格 |
| `CENTER_ECHO` | 中庭回声 | 中央三格 → 左岸两格 → 中央三格 → 右岸两格 |

编辑器的节奏页面可选择这些变体；默认池为每种变体提供独立条目，权重 10、难度 1、最大使用次数 64。添加池条目不会提高地图的节奏关数量，已有地图按原配额随机编排。

## 验收地图

先分别试玩每种启用变体，再对固定种子的整条赛道检查关卡显现、左右镜像、连续换位、侧向推进、掉落恢复与结束清理。正式与试玩使用相同机制；程序测试覆盖编排和状态边界，客户端动画与移动手感需要在支持的 Paper 上实际游玩确认。

躲避关逐项检查四种赛道方向、五档刷新参数、原生垂直碰撞盒、日间燃烧、满员跳过及死亡/出场/取消清理。离线算法或模拟不能代表玩家统计，也不覆盖网络延迟、移动惯性、跳跃、潜行与护盾状态，不能替代当前参数下的原生试玩。

仅 Core 使用 Riptide，Bingo Worker 无此玩法。开发测试从仓库根目录执行 `mvn -B -ntp -pl championships-core -am package`。
