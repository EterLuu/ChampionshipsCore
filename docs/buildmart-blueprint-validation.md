# BuildMart 蓝图、完成判定与遮挡验证

本文提供导入或编辑蓝图后的通用检查方法。地图编辑入口见 [地图指南](map-editing.md)，代码组织见 [开发指南](development.md)。蓝图内容、数量、材料区和建筑地面由部署方配置，不假定某个固定图库。

## 蓝图有效性

- 方块列表必须可解析，BlockData 有效，坐标唯一且位于允许的 7×7×7 范围。
- 蓝图不能为空；错误应包含文件名及条目位置，不通过跳过坏行缩小目标数。
- 只移除展示性地形；船底、台基、舞池和植物必需的基质可能是主体，不能按最低层批量删除。
- 修改方块、布局或难度后重新评星，确认材料清单覆盖实际需求。

材料区保存会生成 `buildmart/material-manifests/<地图>.yml`。缺失或过期清单需先重新保存材料区，才能审查材料可达性。[只读审查脚本](../scripts/README.md#buildmart-审查) 支持 Markdown、CSV 和 JSON 输出；只需 Python 3.11 或更高版本，使用标准库：

```bash
python3 scripts/buildmart_blueprint_audit.py <蓝图文件或目录> \
  --manifest <材料清单.yml> --area-config <地图.yml> \
  --markdown /tmp/buildmart-audit.md --csv /tmp/buildmart-audit.csv
```

尖括号参数需替换为实际文件。工具报告支持的加工来源不能替代当前服务端配方和生存摆放验证。

## 完成判定

展示与玩家建筑都从地板最小角上方一格开始。只比较蓝图记录的目标方块，多余方块不计入完成比例；完整提交和部分得分使用同一匹配入口 `BuildMartBlueprint.blockMatches`。

| 对象 | 匹配规则 |
| --- | --- |
| 普通方块 | 材质与 BlockData 匹配；草方块/泥土、菌岩/下界岩分别视为不同材料 |
| `Fence` 方块数据 | 忽略相邻连接，材质和含水状态一致；具体覆盖范围以服务端 API 类型为准 |
| 关闭的活板门 | 忽略朝向，上/下半位置一致 |
| 打开的活板门 | 忽略上/下半位置，朝向一致 |
| 活板门的其他状态 | 开合、含水、通电状态一致 |
| 栅栏门 | 朝向按轴比较（南/北等价，东/西等价）；开合、嵌墙与通电状态一致 |
| 可生长方块 | 忽略生长年龄，其他状态一致 |
| 树叶 | 忽略自动计算的叶距，种类、持久性与含水状态一致 |
| 铜 | 同形状、同氧化阶段的涂蜡与未涂蜡版本等价，其他状态一致 |
| 门 | 材质与全部状态严格匹配 |

保存时的铜规范化与运行中的匹配是两个步骤：保存会去蜡，并将指定铜部件规范化为未氧化版本；匹配仍区分氧化阶段。材料区和蓝图的保存规则见 [地图编辑指南](map-editing.md#匹配赛建蓝图)。

## 交互保护与生命周期

| 场景 | 检查要点 |
| --- | --- |
| 粘贴与提交 | 普通和黄金区均以各自地板最小角上方一格为原点 |
| 完整与部分得分 | 使用同一匹配规则；只计蓝图记录的目标方块 |
| 材料/状态差异 | 缺失、材质不符、状态不符分别反馈 |
| 展示保护 | 整个展示体积和底部地面覆盖双手、桶、物理、生长、火与爆炸 |
| 流体与活塞 | 不跨独立建筑区或材料区；检查向内与向外移动 |
| 门/床等 | 多方块放置逐格核对 |
| 黄金确认 | 主手、玩家、队伍、槽位和订单代次绑定；轮换/退出清理 |
| 比赛终点 | 不先轮换清除最后订单；保留当前订单进行终局结算 |
| 延迟行为 | 结束/reset/dispose 后旧回调失效，旁观者不参与提交和采集 |

## 六面遮挡检查

编辑器提交时，对每个目标检查东、南、西、北、上、下六个 1×1 接触面。相邻方块须在目标边界处提供完整不透明面；较远的背面或投影不能代替接触面。六面均被封闭时给出提醒，仍允许保存；材料不可达与非法蓝图按各自规则拒绝。

| 方块或环境 | 检查要点 |
| --- | --- |
| 完整不透明方块 | 可以封住相邻接触面 |
| 玻璃 | 透明，不计为完整不透明遮挡 |
| 上/下半砖 | 按实际半格位置检查，不能只看向下投影 |
| 楼梯 | 按原生形状检查缺角和开放侧 |
| 活板门 | 按朝向、开合与实际近面检查，远侧完整面不封住当前边界 |
| 建筑区地面 | 使用该建筑区真实 BlockData，分别核对普通与黄金区 |

分别记录“蓝图自身封闭”和“依赖地面封闭”。前者只读取蓝图，后者需要实际场地上下文；一种地面的结果不能推广到其他建筑区。检查只能识别被紧邻外壳完全封闭的目标，其他目标是否便于观察仍需视线分析和实际游玩确认。

## 原生验证

在支持的 Paper 上分别测试普通、黄金建造和共享展示上下文。验证支撑、六面邻接、红石与调度更新，以及真实生存放置后的 BlockData。直接粘贴成功不能证明所有状态都能由玩家正常放置。

遮挡验证包含上半砖空隙、楼梯缺角、活板门近/远面、透明与不透明地面。记录服务端版本、源蓝图、目标相对坐标、六邻居状态、是否依赖地面和失败原因，使结果可复现。只读审查保持蓝图、世界和发布状态不变，原生验证使用隔离场地。

构建回归从仓库根目录执行：

```bash
mvn -B -ntp -pl championships-core -am test
```

需要迁移其他图库时，应先生成和审核独立清单，保留当前建筑元数据和发布状态；一次性迁移脚本与报告放在 `/tmp`，不作为新地图的通用初始化步骤。
