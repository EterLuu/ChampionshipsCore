# Riptide 编辑器性能检查

地图编辑侧栏会周期刷新，适合显示轻量校验结果；完整赛道规划可能执行大量搜索，不能放入每次 UI 刷新。当前接入方式见 [开发指南](development.md) 与 [关卡指南](riptide-stage-mechanics.md)。

## 展示与完整校验

`PrepareFlowDefinition.validateForDisplay` 为侧栏提供检查入口。Riptide 周期展示检查必填项、几何、材料、速度、种子、建筑尺寸与池容量；主动校验和发布仍进行完整赛道搜索。

侧栏缺项数为零不代表规划已经成功。完整验证需要满足关卡配额、唯一性、难度、动作时间和总限时，不能使用展示校验替代。

## 缓存边界

- 配置持有不可变关卡池及解析结果；替换原始列表后重新解析。
- setter 校验成功后整体发布，无效替换保留有效配置。
- 调用者不能通过列表或嵌套建筑数据修改缓存。
- 内置正向/镜像元数据可复用；改过的建筑使用精确快照重新判断。
- 不增加静态编辑会话缓存或跨线程 Bukkit 访问。

## 验证方法

分别记录轻量校验、完整规划与实际侧栏刷新耗时，包含地图池规模、种子、版本和采样分布。离线算法耗时不等于服务器 MSPT，完整 UI 还包含渲染和发包。

回归检查展示不执行搜索、完整校验仍拒绝不可行地图、编辑立即可见、池不可变、重载/回滚失效及规划确定性。原生测试进入和退出编辑模式，观察 tick、GC、侧栏与旧回调。

```bash
mvn -B -ntp -pl championships-core -am test
```

对大关卡池使用相同输入重复比较，避免用单次本机耗时声称通用性能提升。
