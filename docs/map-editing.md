# 地图编辑与发布

地图编辑统一从游戏内向导进入：

```text
/cc map edit <游戏>
/cc map rename <游戏> <旧场地名> <新场地名>
```

`map edit` 会打开该游戏的地图列表。“新建地图”只建立尚未绑定世界的草稿，不会创建世界。之后可用 `/cc admin world create` 创建或加载世界，站在目标世界中通过向导的“绑定当前世界”步骤进行绑定；重复执行该步骤可更换绑定。已有地图可左键编辑，右键两次删除地图配置；删除地图仅移除配置关联，物理世界删除由 `/cc admin world delete` 独立处理。

`map rename` 只接受空闲且未被 prepare 锁定的地图。它会卸载对应运行实例，同时修改配置文件名、配置内 `name` 和运行时登记名，并迁移正式积分及日常赛数据库记录，然后用新名称重新加载；任一步失败都会回滚数据库、配置文件和原登记。

进入编辑会话后，插件会暂存玩家物品栏，并通过热键栏和步骤菜单引导完成世界确认、schematic、复制布局、出生点、范围、检查点、物品列表等游戏专属配置。需要范围的步骤使用 WorldEdit 选区；列表步骤在 GUI 中新增、编辑、排序或删除。完成后先执行校验，再发布地图。

发布会保存当前物理世界。未发布、存在未保存修改或正被其他管理员锁定的地图不能开赛。同一张地图同一时间只允许一名管理员编辑；正常退出会恢复原物品栏，意外掉线后的快照会在下次加入时恢复。

推荐流程：

1. 执行 `/cc map edit <游戏>`，选择已有地图或新建未绑定世界的地图草稿。
2. 使用 `/cc admin world create <世界>` 准备并加载世界，传送过去后用“绑定当前世界”步骤绑定或更换地图世界。
3. 按步骤菜单完成所有必需点位、范围、列表和复制布局。
4. 使用“校验”检查缺项，再使用“发布”保存地图。
5. 退出编辑模式，使用 `/cc game start ...` 进行单局测试。
6. 检查观战边界、比赛结束、地图重置、大厅返回和积分写入。

斗战方框、激光方盒、跑酷追击、烫手鳕鱼和 TNT飞跃使用各地图的 `schematics/<地图名>/arena.schem` 生成复制场地；匹配赛建保留管理员手建的资源大厅，只选择其边界，并使用 `schematics/<地图>/base.schem` 生成队伍基地。复制场地游戏允许多张地图绑定到同一个物理世界，各地图通过各自的选区、锚点和直线复制布局占用互不重叠的区域；TNTRun 与匹配赛建赛后只恢复本地图的 schematic 区域，不会重载共享世界。匹配赛建 0 号基地只作模板，实际队伍从 1 号基地开始分配；大厅与基地各设置一个传送门落点即可双向路由。复制数量、布局和所有锚点都由各自的向导步骤配置。

激光方盒通过 `/cc map edit laserbox` 编辑：用 WorldEdit 选取完整的 0 号场地，点击“保存场地模板”，再点击“批量生成比赛分区”输入场地总数（包含 0 号场地）。生成保留原建筑，沿 X 轴按模板宽度加 128 格隔离空隙、向上对齐到区块的间距复制；重新生成会先清除原布局的旧副本。双方出生点、观战点、补给点和边界只设置 0 号场地，副本自动平移这些坐标。完成后校验并发布；正式比赛同轮需要至少 `队伍数 / 2` 个场地。

TNT飞跃保存0号赛道模板时会同时记录选区边界，无需另选游戏边界。模板选区决定副本粘贴原点、水平范围和顶部；“设置淘汰高度”单独输入绝对 Y 坐标（`elimination-y`，支持负数和小数），玩家低于该高度时出局，即使此时已在模板底部以下。

跑酷追击的每个复制场地是一整个双赛道对局单元：对局位 A、B 各有一个准备点；赛道 1 同时承载 A 队追击者与 B 队逃跑者，赛道 2 同时承载 B 队追击者与 A 队逃跑者。每条赛道分别配置一个完整活动边界、一个追击者出生点和一组逃跑者出生点，不存在彼此独立的“追击区”和“逃跑区”。

每张地图都可配置赛前规则介绍。设置 `introduction-spawn-point` 和 `rules` 后，玩家会先进入规则介绍阶段；将介绍点留空或把 `rules` 设为 `[]` 即可跳过。

### 匹配赛建蓝图

执行 `/cc map edit buildmart` 并选择地图，在步骤菜单选择“小建筑修改与新建”。点击已有小建筑后，插件会将其放入队伍基地场地 0 的第一个普通建筑区并传送玩家过去；“新建小建筑”先输入名称，再进入空建筑区。修改保留名称和星级，新建时自动评星。

完成后右键该建筑区的实体提交按钮，也可使用菜单的提交按钮或工具栏保存按钮。提交时检查当前地图已保存的材料区快照：无法直接提供或通过支持的合成、烧炼、切石获得的材料会拒绝提交，并保留现场供继续修改。六个方向都被相邻完整不透明面遮挡的方块仅提醒，地面按场地 0 的实际材质检查；楼梯、台阶只按紧邻面的形状判断，玻璃不算遮挡。成功提交后更新蓝图库、恢复临时建筑区并传送至主大厅传送门出生点；取消、退出编辑或掉线时也会恢复建筑区。

用 WorldEdit 选择成品建筑后执行：

```text
/cc map blueprint create <蓝图名> [覆盖星级]
/cc map blueprint audit <蓝图名|all> [地图] [页码]
/cc map blueprint preview <蓝图名|all> [地图] [页码]
```

插件会忽略空气，把方块保存为相对选区最小角的偏移并立即重载蓝图库。蓝图长、宽、高均不能超过 7 格，文件位于 `buildmart/blueprints/<名称>.yml`；目录为空时会写出三个示例蓝图。

蓝图不应包含只用于展示的整片地形底板；船底、篮底、表盘、站台、舞池、主体台基及植物必需的局部基质属于建筑结构，应保留。材料、支撑与判定审查方法见 [BuildMart 蓝图检查指南](../tools/buildmart-review-2026-09-20.md)。

完成判定以蓝图文件为准，展示与玩家建筑均从所选地板最小角上方一格开始。草方块与泥土、菌岩与下界岩不再因上方遮挡而互相替代；额外方块仍按现有规则忽略。活板门、栅栏、栅栏门、生长年龄与铜蜡层的原有匹配规则保留。树叶忽略原版自动计算的叶距，种类、持久性和含水状态仍须一致。普通提交失败会显示缺失、材质错误、状态错误三项数量。加载时坏行、重复坐标、越界、空蓝图会整张拒绝并记录文件名和列表项编号；导出时拒绝现场缺少支撑的方块。

各队三个普通建筑区的提交按钮正上方三格会显示当前蓝图的全部材料，每行两种，格式为“橡木 × 4  涂蜡的切制铜台阶 × 1”；材料名称采用客户端原版译名。数量按实际放置材料统计，双层台阶计两块，门、床和双格植物按一件计，墙面告示牌/旗帜使用对应物品名，盆栽列出花盆与植物；订单完成时移除，下一张订单出现时更新，黄金建筑区不显示。玩家携带的资源地图绑定当前场地世界，每位玩家只看到自己的位置和朝向，超出地图范围时在边缘显示自己的标记。

黄金轮换共用比赛倒计时，比赛终点保留当前建筑结算部分得分；黄金两次确认只接收主手，并绑定玩家、队伍、槽位和本轮订单。普通及共享黄金展示区按完整 7×7×7 空间和底部地面保护交互与物理变化，流体和活塞不能跨越独立建筑区/材料区边界；门、床等多方块放置逐格校验。

建材区各自独立补货：成功采集后开始计时，每次再次采集都会重置计时，连续 20 秒无人采集后恢复该区域的方块快照。未被采集的区域不会定时刷新；比赛开始和地图重置时仍会恢复全部建材区。

匹配赛建中的铜不会自然氧化，蓝图匹配和材料审查不区分涂蜡状态。保存蓝图时会去除全部铜蜡层；凡是不能由同氧化阶段完整铜块即时合成或切石获得的部件（铜栏杆、铜链、铜箱、铜门、铜傀儡雕像、铜灯笼、铜活板门、避雷针），都会统一成未氧化版本。保存材料区时也会把涂蜡铜快照规范化为同氧化阶段的普通铜。

保存匹配赛建材料区时，插件会扫描当前选区并生成 `buildmart/material-manifests/<地图>.yml`。该文件按材料区和总计记录非空气方块的 `minecraft:<material>` 数量，同时保留精确 `BlockData` 数量，供检查全部建筑的材料需求是否被资源大厅覆盖，也是编辑器提交小建筑的材料审查依据。清单缺失或快照已变化时会拒绝提交，需重新保存材料区。

可使用 `scripts/buildmart_blueprint_audit.py` 检查单张蓝图或整个蓝图目录。脚本会结合方块数、材料种类、材料岛数量、高度、离散结构、方向和其他 `BlockData` 复杂度生成难度分数，并依据材料清单报告直接覆盖、可合成覆盖和未覆盖材料。例如：

```bash
python3 scripts/buildmart_blueprint_audit.py <蓝图文件或目录> \
  --manifest <material-manifests/地图.yml> \
  --area-config <areas/地图.yml> \
  --markdown buildmart-audit.md --csv buildmart-audit.csv
```

## 资源目录

以下路径相对于 Core 的插件数据目录 `plugins/ChampionshipsCore/`；具体地图名称由编辑器创建。

```text
maps/                           # 已发布世界的静态模板
buildmart/
  areas/                        # 地图定义
  blueprints/                   # 共享建筑蓝图
  material-manifests/            # 自动生成的材料清单
  schematics/<地图>/base.schem   # 队伍基地模板
  schematics/<地图>/material-zones/
bingo/
  areas/
  cards/
  lang/
  tags/
  tierlists/
skywars/variants/default.yml    # 可复制修改的规则方案
```

BattleBox、ParkourTag、LaserBox、HotyCodyDusky 与 TNTRun 的场地模板位于各自目录的 `schematics/<地图>/arena.schem`。资源和配置模板位于源码 `championships-core/src/main/resources/`；目录并不意味着仓库附带可直接开赛的完整地图。

地图改名的资产与数据库事务见 [改名契约](map-rename-contract.md)。修改地图前备份数据目录与数据库，并在空闲窗口保存、重载或编辑场地配置。
