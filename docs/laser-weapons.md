# Laser 枪械接入

Core 的 LaserBox、LaserShowdown 和后续 Laser 类玩法共用 `api/game/laser/`。枪械包不依赖任何具体游戏的场地、队伍、计分、地图或旁观名单。

| 职责 | 入口 |
| --- | --- |
| 枪械材质、弹匣、射速、换弹时长、射程、散布、后坐力、命中部位伤害和距离衰减 | `model/LaserGun` |
| 弹药、手动/自动换弹、连射和射击截止时间 | `runtime/LaserWeaponState` |
| 姿态散布、射击方向、命中部位和枪声 | `mechanics/LaserGunMechanics` |
| 方块遮挡、实体射线、逐弹丸统计和单次射击伤害合并 | `mechanics/LaserShotEngine` |
| 武器及弹药物品、激光、开镜与击杀反馈 | `presentation/LaserGunItems`、`LaserBeam`、`LaserZoom`、`LaserKillFeedback` |
| 参赛者头顶名字隐藏与记分板恢复 | `presentation/LaserNameTags` |

每个对局创建独立 `LaserWeaponState`，以 UUID 保存状态。游戏传入当前对局 tick 和统一游戏资格；`shoot` 返回开火、冷却、换弹中或未就绪。射速以每秒发数定义，射击截止时间累积小数 tick，在整 tick 执行时保留余量；连射散布仍以 quarter tick 静默窗口计算。弹匣耗尽自动开始换弹，手动换弹调用 `requestReload`。热键切换和间接换手都须调用 `cancelReload`；完成换弹前确认当前玩家仍有游戏资格且持有原枪，调用 `completeReload`。

成功开火后调用 `LaserShotEngine.fire`。其 `Context` 由玩法提供：`current` 复核当前场地、比赛身份和射手资格，`collidable` 定义能挡住射线的实体，`enemy` 定义可受伤的敌人，`beam` 选择查看者并调用共享粒子呈现。可选的 `pelletHit` 接收每颗敌方命中弹丸供统计使用；`damage` 接收一次射击对每个目标合并后的伤害及命中部位。友军可挡住射线但不会触发敌方命中统计。旁观者通过统一游戏资格排除。引擎在每颗弹丸和每次伤害前重新检查当前资格，不调度延迟攻击。

特殊实体通过 `collidable` 纳入，并由 `intercept` 处理。LaserBox 在此接入烟幕弹拦截；护盾、特殊道具、分数转移及重生保护继续由 LaserBox 负责。LaserShowdown 在逐弹丸回调累计命中统计，换枪窗口、多队伍关系及击杀计分由其自身负责。

同一条命换枪调用 `equip` 更换弹匣并取消换弹，保留原射击截止时间；新生命调用 `forget` 清除该玩家旧弹药、换弹和连射状态。重连同一条命需要保留弹量时，在恢复装备后调用 `setAmmo`。结束、失败、中止和释放对局调用 `close`，旧实例关闭后不再接受射击或重建状态；reset/新局使用新的实例。游戏仍负责取消自身任务、校验延迟回调的比赛代次，并在死亡、退出、结束及卸载时恢复开镜、冷却和移动效果。

狙击枪开始手动或自动换弹时立即结束开镜，换弹期间不接受新的瞄准输入；换弹完成或中断后可重新开镜。自动换弹之前的最后一发沿用开火瞬间的瞄准状态。不开镜时额外增加 6° 散布，包括首发和蹲伏；开镜精度保留，放大呈现参数为 20。

两种玩法共用持枪移动效果：步枪无加速，霰弹枪速度 I，冲锋枪速度 II，机枪和狙击枪缓慢 I；狙击枪开镜使用缓慢 III。切枪时立即替换效果等级，切换到其他武器时清除旧缓慢；空手及仅持弹药时沿用速度 II。效果由当前对局维护，在死亡、退出、结束和释放时清理。

LaserShowdown 首次准备在分配出生点、发放装备和传送完成后自动打开选枪菜单，倒计时 15 秒后开赛；后续回合保留选枪结果并倒计时 5 秒。倒计时期间允许正常移动和落地，由场地区域限制活动范围。规则介绍期间沿用共用介绍保护，不按正式比赛的分区边界反复传送玩家。

两种玩法在比赛阶段共用 `LaserNameTags` 隐藏头顶名字。已有记分板队伍仅调整名字可见性，保留队名、成员、前后缀、颜色、碰撞及其他属性；无队伍条目使用临时队伍。各对局共享记分板租约，结束、reset/dispose 或切换记分板时只释放自己的租约，避免旧局清理覆盖新局。重连和记分板刷新由当前连接的实体线程捕获，关闭后的捕获不再生效。名字隐藏不操作实体显隐、玩家信息或 Tab 列表；真实离线仍由原有玩家信息流程移除。

枪械包只在调用方现有线程同步执行。操作真实玩家、实体和发包时必须遵守 [旁观契约](spectator-visibility-contract.md) 与 [UUID 契约](player-uuid-contract.md)，不能用枪械状态代替统一旁观身份或另建调度流程。

玩家文案沿用现有 `message.yml` 的 `laser-box` 及 `code-text.laser-box-area` 枪械键，保留已安装的自定义名称、说明和颜色；物品标记键由玩法传入，避免与其余玩法道具冲突。新增玩法复用这些枪械文案与呈现入口，无需复制枪械配置或算法。

共享算法和状态测试位于 `src/test/java/.../api/game/laser/`，具体玩法测试仍验证计分、角色和生命周期接入。Laser 类玩法仅在 Core 的 Paper 服务端运行；Folia 仅供 Bingo Worker 使用，未使用枪械包，无需为 Laser 游戏加入 Folia 兼容实现。
